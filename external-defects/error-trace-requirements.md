# Error-trace 功能需求与优先级

本文依据 D13/D8/D4 的真实设计错误、S3/D12 的执行停驻，以及 S2 的内部连接回归提炼后续功能需求。前三例的机制分析仍绑定 [failure-analysis.md](failure-analysis.md) 中历史 CSV 批次与保存状态；新增证据单独绑定当前外部 CLI 双执行批次。当前10个变体的VCD主协议全部通过，第五份 indexed read 语义补丁后全部20组、2568份逐次状态的完整连接审计也通过。历史AutoConnect修改引入的S2回归仍是真实诊断材料；不能只由VCD通过推定内部完整性，也不能据本轮规避宣称K/LLVM backend已修复。本轮没有开发或验收新的Error-trace查询能力。

P0 表示后续最小可信诊断入口必须具备；P1 表示提高源码解释和复用效率；P2 表示在正确性通过后再优化。优先级不等于本轮实施授权，不构成冻结 spec、技术设计或实施计划。

关键原字节工件的来源与 SHA256 见 [evidence/index.json](evidence/index.json)。新增执行失败、元数据回归和前后版本审计分别索引于 [VCD 执行失败](evidence/vcd/execution-failures/vcd-complete-01/README.md)与[元数据证据](evidence/vcd/metadata-integrity/vcd-complete-02/README.md)。完整 `.runs` 保留历史命令、事件序列和旧路径；当前共享文档链接指向精简结果和选定证据，旧 source location 通过原文件哈希及设计 layout 关联。

## 2. P0：先保证诊断结论可信

### R1. 首次差异应成为稳定、带观测阶段的查询入口

- **证据**：E1 的 D13 sample 5 / event 10；E2 的 D8 sample 4 / event 8。两例缺陷 K 与原生一致，但都违反 oracle。
- **目前缺什么**：runner 已有首次差异 JSON，尚无把该记录解析成唯一状态、实例和信号的诊断入口；进程退出码及单一 `pass/fail` 不能表达仿真器一致性与设计缺陷是否被检出。
- **预期查询结果**：返回案例/变体/后端、sample/event、phase、完整信号路径、位宽、expected/actual、oracle 来源和对应状态哈希；单独标明 `simulator_agrees_with_native` 与 `bug_detected_by_oracle`。
- **验收**：从既有 D13 记录准确定位 `axis_frame_len/frame_len:i16, event=10, expected=1, actual=3`；D8 准确定位 `axis_switch/m_axis_tvalid:i1, event=8, expected=1, actual=0`。不得把缺陷正常被 oracle 拒绝标为仿真器错误，也不得以退出码 0 覆盖差异。

### R2. 有界跨事件寄存器追溯必须同时给出旧值、待写值和提交条件

- **证据**：E1 中 D13 event 8 的旧 len=2、增量=1、正常/缺陷待写值=1/3，event 9 提交；E2 中 D8 event 6 的输出 valid 待写值=1/0，event 7 提交，event 8 才形成规定顶层观测。
- **目前缺什么**：状态都在，但还需要人工选择相邻事件、查找寄存器 SSA 并区分组合计算、寄存器提交和端口观测；只在寄存器停止会遗漏真正影响其输入的条件。
- **预期查询结果**：在用户指定的事件上界/下界内返回寄存器旧值、数据输入、复位/时钟/使能条件、提交事件及来源操作；区分“寄存器已经提交”与“顶层端口已在本事件观察到更新”。
- **验收**：D13 从 event 10 回到 event 8/9，给出 `2 + 1 = 3` 及应清零条件；D8 从 event 8 回到 event 6/7，给出输出侧 valid 的输入0及真实采样差异。不能在 D8 event 7 把内部寄存器值 1/0冒充该事件保存的顶层端口值 0/0。越过指定边界必须显式返回“追溯边界已到”，不能猜测更早状态。

### R3. 控制依赖和位选择必须按实际执行值解释

- **证据**：D13 的 `last=1` 绕过缺陷版清零分支；D8 的 `int_axis_tvalid=2:i4, grant_encoded=1, grant_valid=1`，正常索引1、缺陷索引4导致 valid_mux=1/0。
- **目前缺什么**：存在操作值和源码，但尚无按实际条件选择依赖边的查询；若只沿数据操作遍历，D13 会误停在加法，D8 会误停在输出寄存器。
- **预期查询结果**：mux 的条件与实际所选输入、and/or 的各操作数、索引算式及位宽、移位量和选中位；分别标记数据与控制依赖，并沿 `hw.instance` 参数/返回值保留实例路径。
- **验收**：D13 显示 `last=1`、缺陷基值选择2、增量1；D8 显示 `grant_encoded*M_COUNT+n=1` 对 `grant_encoded*S_COUNT+n=4`，4位总线右移4结果0，并穿过 `m_ifaces_0.reg_inst` 的 valid 输入。不得把本配置未触发的 ready 索引差异称为本次已证明根因，不得添加没有执行依据的内存写依赖。

### R4. 查询必须绑定真实工件版本，并可从保存状态确定性恢复

- **证据**：E1/E2 的 `.kore.gz` 与 `events.json` 已带未压缩 SHA256；E3 绑定源文件和 IR；E4 离线读取逐一核验这些哈希。正常/缺陷 `%219` 在 D8 中不是同一个寄存器角色。
- **目前缺什么**：工件已齐，但尚无统一的诊断输入包校验和按事件恢复接口；只用文件名、SSA编号或最近的构建缓存会连接错误版本。
- **预期查询结果**：校验源/IR/状态哈希、manifest 参数和初始化契约；以“IR版本 + 实例路径 + SSA + event”标识节点；直接加载既有 checkpoint，或从已校验 setup 加事件序列重放。
- **验收**：对 E1/E2 的全部指定窗口校验成功并返回相同 SSA 值；修改任一被引用工件的哈希后明确拒绝该版本组合；两个案例、两版、重复查询之间不能共享上次查询的节点容器或污染结果。重放不得遗漏 reset 或擅自把未定义 CSV 输入变成0。

### R10. 报告实际残留操作，并独立验证只读状态未被改变

- **证据**：E6 中 `vcd-complete-01` 的 S3 golden 在 event 0 / evaluation 2 失败，D12 golden 在 event 9 / evaluation 1 失败；最后 `krun` 均返回 0，CLI 终态检查报 `未清空 []`，实际仍有 `current-info` 与 operation。两案三次重放均逐字节复现。E9 的前后版本对照确认本轮 AutoConnect 修改在 S2 引入元数据回归：complete-02 全部顶层 VCD 通过，但 S2 golden 从 event 84 / evaluation 2 起的 9 份状态仍改变只读 connection，说明无残留 current 也不能替代元数据完整性检查。S3 在前一 evaluation 的 depth 1956→1957 改变 `connection[%131]`，D12 在 event 8 / evaluation 2 的 depth 942→943 改变 `connection[%69]`。
- **目前缺什么**：原始状态与工具退出码保住了失败事实，但错误摘要未给出残留的 current、READ 阶段、SSA 和实际参数；人工需要限定执行步数并比较相邻完整状态，才能发现列表早于最终失败已损坏。
- **预期查询结果**：报告运行/定义身份、phase、event/evaluation、current-id、实例/SSA、原始 IR 参数、connection 参数与当前实际参数及位宽。独立于 VCD/终态通过，对声明为只读的 connection 提供首个变化的前后状态、规则位置、键和顺序差异；明确区分首次状态损坏、后续语义停驻与最终错误观测。
- **验收**：S3 返回 `%131` 的 `[%124,%28,%112] → [%28,%112,%112]`；D12 返回 `%69` 的 `[%57,%65,%70] → [%65,%70,%70]`；S2 返回 `%53` 的 `[%51,%50,%54] → [%50,%54,%54]`，同时保留该批顶层 VCD 通过这一真实观测。不能把 `krun=0` 当作事件完成，不能把错误中的空列表解释为没有待执行操作，也不能把序列化单步重启未复现当作原连续执行不存在问题。规则和进程内共享结构已有证据，尚未单独定位的 LLVM runtime hook 必须保留不确定性。

### R11. 语义覆盖与停驻原因应按操作形状区分

- **证据**：E7 中 D11/C4 的历史首事件 120 秒超时，随后静态检查确认 `hw.array_inject` 无生效规则、数组 mux 与数组 firreg 注册/初始化形状未覆盖；补充一维整数数组语义后按原输入完成 VCD 对照。E8 中 S2 旧 IR 留有 LLHD，parser 在进入事件执行前失败；受限初值转换与 preset 支持具有单独来源证明。
- **目前缺什么**：仅列 operation 名称或看到源文件中的规则不能证明具体类型、属性、范围已被当前定义覆盖；统一 timeout 也无法说明缺规则、类型不匹配还是执行成本。
- **预期查询结果**：绑定当前编译定义，按完整 operation 名称、operand/result 类型、必要属性和运行值宽度给出已覆盖形状、明确不支持边界及停驻状态。将解析失败、未匹配语义、完整性检查失败与资源超时分别记录；证据不足时返回未知，不从超时推定性能原因。
- **验收**：历史 D11/C4 指出正位宽一维数组的实际缺口及规则所在生效导入闭包，不能把 backup 文件算作支持；S2 区分原 LLHD 输入与 `constant-initial-register-v1` 已证明转换后的版本。不得把已验证的二态、有效索引、一维整数数组扩展成任意聚合、非法索引、四态、异步复位或通用 LLHD 支持。此项是后续诊断需求，不意味着本轮已实现自动覆盖分析。

## 3. P1：使解释能够回到可维护的源码区域

### R5. 操作、层次与源码映射应显示精度和缺失情况

- **证据**：E3 中 D8 `#loc113/#loc114` 指向 `axis_switch*.v:301`，可直接对应 valid 选择；D13 缺陷基值 mux 的 `#loc12` 只指向第70行，D8 多个输出寄存器被归到 `axis_register.v:89`。IR 同时存在 unknown/fused location。
- **目前缺什么**：已有并行 debug IR 和操作顺序映射，但尚未验证诊断节点到源码的完整身份关系，也未向使用者表达“精确范围、合并范围、声明位置、缺失位置”的差别。
- **预期查询结果**：给出模块/实例/SSA、操作类型、执行IR与调试IR哈希、原始location和可打开的源码区域；无法精确定位时保留IR节点并说明来源精度。
- **验收**：D8 位选择链能回到第301行；D13 正常清零条件能回到81–83行；缺陷mux第70行位置必须保留原样并标注其局限。不能用当前工作树中同名源码替代已绑定版本，也不能把 unknown location 捏造成源码行号。

### R6. 正常/缺陷辅助对照应支持条件缺失和操作重排

- **证据**：D13 正常版新增“上一帧完成则清零”，缺陷 IR 不存在该条件；D8 正常/缺陷 valid mux 之前多出一个 concat，随后 SSA 编号整体变化。
- **目前缺什么**：人工已通过源码diff和对应寄存器角色建立对照，尚无保持版本与语义角色的辅助映射。简单按同一SSA编号或同一行号对齐会错配。
- **预期查询结果**：在提供正常版材料时，展示相同可观察故障区域的两条实际计算链和相关源码diff；将缺失条件表示为正常侧独有的区域，不制造缺陷侧不存在的节点。没有正常版时仍能输出单侧证据和剩余不确定性。
- **验收**：D13 对照基值0/2及对应清零策略；D8 对照位移1/4及同一输出寄存器角色。不得仅因源码有两处diff就宣称本轨迹触发两处故障；也不要求自动给出修复补丁。

### R7. 诊断结果应保留初始化、二态和采样协议的适用范围

- **证据**：D13 TB 参数与DUT默认参数不同；D8 原TB只支持二态且比完整CSV少最后一条观测；D8 event7内部寄存器与顶层导出值的阶段差别已被保存状态直接观察到。
- **目前缺什么**：manifest和采样说明已记录这些条件，但未来诊断若只展示一张依赖图，容易丢掉结论依赖的配置和时序范围。
- **预期查询结果**：每份报告附真实参数、初始化来源、二态/四态假设、CSV masks、规定观测阶段、原TB对照覆盖范围及未核对中间事件。
- **验收**：D13报告保持KEEP_WIDTH=8；D8报告明确14条CSV与13条原TB共有前缀的区别，禁止宣称通用四态/SV调度等价。诊断须始终可返回R1绑定的观测契约。

### R9. firmem 写入应按真实地址、使能和提交事件关联先前值

- **证据**：E5中D4 `seq.firmem<32 x 10, mask 1>`；正常/缺陷event134写地址都为2，但使能0/1。event135正常mem[2]仍2、缺陷变1；缺陷前一次对地址2使能的写由event34准备、event35提交，数据2。event132/133还有地址1、数据0的最后一笔共同合法写。
- **目前缺什么**：原始内存、写口操作和状态都已保存，现阶段只能离线人工扫描；尚无区分实际写、禁用写、其他地址写和内存声明的查询接口，也没有按地址关联最近提交的写入。
- **预期查询结果**：返回内存实例/SSA、地址及位宽、使能、写数据、有效掩码范围、写延迟、准备与提交事件、旧值/新值，以及同地址上一次真实写入。随后可沿写使能回到指针/满条件与背压，沿写数据回到输入。
- **验收**：从D4缺陷event135的mem[2]=1回到event134地址2/使能1/data1，再连接event35的旧值2；正常event134使能0不能形成写依赖，地址1的event133也不能被当作地址2的最近写。报告本例整10位写入、读延迟0/写延迟1，不把该证据扩展成动态部分掩码、多写口冲突或数组寄存器追溯已实现。该需求依据D4真实存储覆盖材料列为P1，仍属后续开发。

## 4. P2：在解释正确后降低人工核查成本

### R8. 对同一真实失败提供有界摘要和按需展开

- **证据**：E4 已能保存完整SSA窗口，但人工只需要 D13 的基值/增量/寄存器链和 D8 的仲裁/索引/valid寄存器链即可核对本次机制；完整K状态和IR仍需保留以复核被省略部分。
- **目前缺什么**：所有状态都可以读取，但没有经验证的摘要、查询预算或相同子链复用机制。
- **预期查询结果**：默认展示规定事件区间内的关键操作和值，允许展开完整依赖；显示截断边界、查询耗时、节点数和工件链接。缓存以版本与事件身份为键。

## 5. 证据不足时暂不进入实现优先队列
